# Prototype

Throwaway code that answers one question. Its output is a decision, not a feature.

1. Write the question and what answer would change your mind, before writing code.
2. Build it outside the main tree: `.work/prototypes/<slug>/` or a scratch worktree. No tests, no polish.
3. For a design fork, build 2-3 competing sketches (parallel `rstack:implementer` agents, one each) and compare side by side.
4. Run it. Record what you observed, with output.
5. Write the decision to the spec or an ADR (only if it qualifies). Keep the decision-rich snippet (type, state machine, schema), delete the rest.

Reply: the question, what you built, what you observed, the decision.
